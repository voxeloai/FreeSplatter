## 09:42 UTC — run 2 FAILED at step 6d.2 (kernel compile)

- nvcc auto-detected sm_86 (A6000) correctly: `-gencode=arch=compute_86,code=sm_86` in the build line. Good.
- Kernel diff-surfel-rasterization (commit e0ed020) failed compiling `cuda_rasterizer/rasterizer_impl.cu`:
  - `namespace "std" has no member "uintptr_t"` at rasterizer_impl.h(24)
  - `identifier "uint32_t" is undefined` at rasterizer_impl.h(40), (41), (49), (58)–(61)
- Cause: header includes `<iostream>`, `<vector>`, `<cuda_runtime_api.h>` only. Under gcc 13.3 / CUDA 12.8, these no longer transitively expose `<cstdint>`. Newer libstdc++ is stricter.
- Same issue is fairly common with older 3DGS-derived rasterizer code on modern toolchains — searching the web confirms multiple repos hit it on Ubuntu 24.04 / gcc 13.

## 09:43 UTC — patched bootstrap.sh step 6d.2 (cstdint fix)

- Added before `uv pip install --no-build-isolation -r /tmp/req-git.txt`:
  ```
  export NVCC_PREPEND_FLAGS="${NVCC_PREPEND_FLAGS:-} -include cstdint"
  export CXXFLAGS="${CXXFLAGS:-} -include cstdint"
  ```
- `NVCC_PREPEND_FLAGS` is an official nvcc env var that prepends to every nvcc invocation; nvcc accepts `-include` (passes to host preprocessor in host phase, includes for device code too).
- `CXXFLAGS` covers the pure-C++ paths torch's build_ext takes outside nvcc (e.g. binding files compiled directly with gcc).
- Pattern-level — will lift to bypass-conda decision doc + PATTERN.md template.
